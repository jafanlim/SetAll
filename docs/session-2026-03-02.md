# SetAll — Dev Session Notes
**Date:** 2 March 2026

## Bugs Fixed

### 1. Split Duplication → 2× Balance Bug
**Root cause:** `addExpense` and `updateExpense` generated a new UUID for each split when inserting locally into SQLite, then generated *another* new UUID when inserting into Supabase. On `_syncFromSupabase`, the Supabase rows arrived with different IDs and were inserted as *additional* rows (instead of replacing), doubling every balance.

**Fixes applied:**
- `setall_repository.dart` — Generate stable split UUIDs once in `addExpense` / `updateExpense`; reuse the same UUID for both the local SQLite insert and the Supabase insert.
- `setall_repository.dart` (`_syncFromSupabase`) — Changed from a destructive delete-then-insert to `INSERT OR REPLACE` which leverages the new `UNIQUE(expense_id, user_id)` constraint. Local rows that Supabase is missing (e.g. from a previously failed INSERT) are preserved.
- `local_database.dart` — Schema v9: deduplicates existing stale split rows on upgrade (`DELETE … WHERE rowid NOT IN (SELECT MAX(rowid) …)`) and adds `UNIQUE INDEX idx_splits_unique_pair ON splits(expense_id, user_id)` to prevent future duplicates.

---

### 2. Supabase RLS Migrations
Two SQL migrations were applied via the Supabase SQL Editor:

**`20260302000003_fix_expense_update_rls.sql`** (made idempotent — added missing `DROP POLICY IF EXISTS` guards):
- Dropped overly-restrictive `"Expense payer can manage splits"` policy.
- Created `"Group members can manage splits" FOR ALL` — any group member can insert/update/delete splits in their groups.
- Created `"Group members can update/delete expense"` policies — any member can edit expenses, not just the original payer.

**`20260302000004_get_group_members_rpc.sql`**:
- Created `get_group_members(p_group_id UUID)` as a `SECURITY DEFINER` RPC.
- Bypasses the restrictive `group_members` SELECT RLS that was returning only 1 row (the caller), causing splits to only include 1 participant.
- Security: only returns members of groups the caller already belongs to (enforced via `get_my_groups()`).

### 3. Percentage Split Rounding — Remainder to Payer
**Bug:** With 3 members, even split in `%` mode displayed as 33 / 33 / 34, assigning the extra `1%` to the *last person* in the list (arbitrary), not the payer.

**Fixes:**
- `split_engine.dart` (`splitEven`) — Added optional `payerId` parameter. The remainder cent now goes to the payer's slot, not index 0.
- `add_expense_screen.dart` (`_rebuildControllers`) — Switched from integer `100 ~/ n` to 1 decimal place: `33.4 / 33.3 / 33.3`. The `0.1` remainder goes to whichever slot matches `_payerId`.
- `edit_expense_screen.dart` (`_rebuildControllers`) — Same fix.
- Both `_submit` methods now pass `payerId:` to `SplitEngine.splitEven`.

## Desktop UX Refactor

### 4. ScreenUtil — Disable Scaling on macOS
**Problem:** `ScreenUtil` was initialised with a 390×844 iPhone design size. On a 1400px macOS window, `1.w ≈ 3.59px` — every button, font, and padding was ~3.5× oversized ("Giant Button Syndrome").

**Fix (`app.dart`):**
- On macOS / Windows / Linux, pass `designSize = MediaQuery.sizeOf(context)` (the actual window size) so every `.w` / `.h` / `.sp` call is a **1:1 identity transform**.
- `minTextAdapt: false` on desktop — text never re-scales.
- Mobile still uses the 390×844 iPhone 16 Pro baseline.

---

### 5. Window Manager — Minimum Window Size
**Added dependency:** `window_manager: ^0.4.3`

**Fix (`main.dart`):**
- On desktop, `windowManager.ensureInitialized()` runs before the Flutter app.
- Default window size: **1100×720**.
- Minimum window size: **800×600** — the UI can never be shrunk to an unusable size.

---

### 6. Master-Detail Split View
**Problem:** Tapping a group pushed a full-screen route, consuming the entire window — a mobile pattern inappropriate for macOS.

**New files:**
- `lib/core/providers/desktop_providers.dart` — `selectedGroupProvider` (`NotifierProvider<SelectedGroupNotifier, SelectedGroupState>`) holds the active `{groupId, groupName}` for the detail pane.
- `lib/core/utils/navigation_utils.dart` — `navigateToGroup()` helper: on desktop (≥ 900px) sets `selectedGroupProvider`; on mobile/tablet pushes the GoRouter route as before.

**Modified files:**
- `lib/core/layout/adaptive_shell.dart`:
  - New `_buildDesktopLayout()`: sidebar (200px) + master list (capped at 780px via `ConstrainedBox`) + `VerticalDivider` + `GroupDetailScreen` detail pane (or `_DetailPlaceholder` when nothing is selected).
  - `_onTap()` clears `selectedGroupProvider` when switching nav tabs.
- `groups_screen.dart`, `dashboard_screen.dart`, `friends_screen.dart` — all group taps now use `navigateToGroup()`.
